## 1 · Architecture Overview

```
                  ┌─ loa-hounfour (THE LAW) ──────────────────────────┐
                  │  Veve TypeBox schema + constraint file + vectors    │  (cycle-1 handoff, like Legba #118)
                  │  keyring + signature-envelope shapes (reused)        │
                  └───────────────┬─────────────────────────────────────┘
                                  │ vendored shapes, not runtime imports
   packages/asson/ (@freeside/asson · network domain · zero-NPM-dep core)
     src/asson.mjs        jcs · sha256 · treeHash · attestBuild/verify · invoke ·
                          runVectors · harvestVector · toCommandPolicy · doctor
     src/liveness.mjs     budgetStatus · detectStall/Spin · paceCheck ·
                          checkpointPacket · livenessVerdict  (over Legba span logs)
     src/vendor/canon.mjs VENDORED jcs+ed25519+keyid from legba-core.mjs (+ conformance test)
     schemas/veve.schema.json   the staging shape (ajv-validated in tests)
     examples/{wordcount,lexicon-lint}/   worked L3 CLIs (bin + veve + harvested vectors)
                                  │
                                  ▼ asson policy
   loa-finn CommandPolicy  ◄── generated, never hand-authored (x_determinism, x_veve_tree_hash,
   (src/agent/sandbox.ts)      x_timeout_s, x_rel_required) — cycle-5 spawn-time verify PROPOSAL
                                  │
   the comms seam (cycle 5): THREE INDEPENDENT LINTERS
     ai-stench-check.mjs (voice) · vocabulary-bank (product) · asson lexicon-lint (LEGAL register)
```

Three fixed positions:

1. **Vendor the ceremony, prove conformance** (B6) — asson does not import `legba-core.mjs`; it copies the ~30-line JCS+ed25519+key-id primitives into `src/vendor/canon.mjs` with a provenance header **pinning the exact `legba-core.mjs` source SHA it was vendored from** (B3). `test/canon-conformance.test.mjs` asserts byte-identical output to Legba on a SHARED, VERSIONED fixture corpus (`test/fixtures/canon-corpus.json`). **Propagation policy** (B3): the conformance test is the tripwire — when Legba's canon changes (the pinned SHA moves), the test goes RED on the next run, forcing a deliberate re-vendor + corpus update (a PR, reviewed). A Legba security patch to canon is therefore a loud, gated event, not a silent drift. The provenance header carries `// re-vendor when legba-core.mjs moves past <SHA>`. Zero-NPM-dep + self-contained + fork-proof-with-a-tripwire.
2. **Evidence promotes, claims are checked** — `doctor()` computes EARNED level from {veve valid? + vectors pass? + attestation valid? + determinism honest?}; the `claimed` field never feeds enforcement (AS-3). Mechanical drift fails; judgment (`declared_by: author`) warns.
3. **The veve is the law, staged for hounfour** — the schema lives in `packages/asson/schemas/` now, ships as a hounfour PR (TypeBox + constraints + ≥10 vectors) — the concrete pass/fail the PRD §8b demands.

## 2 · Technology Stack

| Layer | Choice | Justification |
|---|---|---|
| Core | zero-NPM-dep `.mjs`, `node:crypto` only | Matches Legba + the reference; runs everywhere; the package preaches self-containment, so its core embodies it (OQ2 leans `.mjs` for cycle 1; Effect is the *graduation dialect*, not the core's) |
| Canonicalization | vendored RFC-8785-subset JCS (`src/vendor/canon.mjs`) | Byte-identical to Legba (conformance test); full RFC-8785 swapped only when a non-node producer appears (OQ6) |

The `doctor` and the freeside-cli verbs are dev/CI tools and MAY take deps; ajv is the doctor's veve validator. This resolves the contradiction: `asson.mjs` primitives are zero-NPM-dep; `doctor()`'s schema check uses ajv (or a vendored minimal validator if a fully-zero-dep doctor is later wanted) |

| Verbs (cycle 2) | `@freeside/freeside-cli` | ADR-007 home (doubled name); scaffold present |

## 3 · Data Models

### 3.1 Veve (the manifest — `schemas/veve.schema.json`, staged for hounfour)

Fields per the reference schema (verified): `veve_version {0.1.0|0.2.0}` · `name` (slug) · `version` (semver) · `summary` · `binary {entry, runtime, subcommands}` · `determinism {class: re_executable|attestable, declared_by: author|effect_type|trace_audit, ambient[]}` · `rel_required {casual|competitive}` · `liveness {timeout_s, expected_p95_s, mode: oneshot|daemon}` (required at 0.2.0) · `io {input, output, output_schema, exit_codes}` · `vectors[] {name, argv, stdin, expect_output_hash, expect_exit}` (AS-12) · `ladder {level 1-5, promoted_from, evidence_runs[]}` · `attestation {tree_hash, git_commit, signed_by_key_id, signature, ts}`.

Version dispatch (fork-train): `allOf` requires `liveness` iff `veve_version == 0.2.0`; 0.1.0 valid-but-warned (the demo's fork window). Constraint file (hounfour) adds: `class=re_executable ⇒ network ∉ ambient`; `vectors.length ≥ 1` for L3 re_executable; `attestable ⇒ ambient non-empty`.

**`evidence_runs[]` shape + verification** (IMP-005, B5): each entry is `{run_id, ts, source: recorder|git-log}`. The doctor VERIFIES each `run_id` resolves in the recorder (`.run/cycles/*/flight-recorder.jsonl`) or as a git-log commit touching the `promoted_from` path — an unverifiable run_id does NOT count toward L2, and a veve whose L2 rests entirely on unresolvable evidence_runs earns L1 (not L2) with a finding. This closes the fabrication hole (B5): synthetic run IDs grant nothing; recurrence is sensed from real records (AS-11). `declared_by: author` at L2 also warns (not only L3+).

**Liveness defaults** (IMP-003 — concrete thresholds for reproducible verdicts; magnitudes are ergonomics, soundness is the existence of the value): `DEFAULT_POLICY = { stall_s: 120, spin_repeats: 3, budget_calls: <veve.liveness or 50>, pace_p95_factor: 1.5 }`. `detectStall` fires at `nowMs - lastMoveMs > min(timeout_s, stall_s)`; `detectSpin` at the same (tool, input_hash) appearing `≥ spin_repeats` consecutively; `paceCheck` at elapsed `> expected_p95_s × pace_p95_factor`. These are the demo's values, pinned so conforming implementations agree.

**Optional-field fallback** (IMP-009 / AS-16): a 0.1.0 veve (no `liveness`) or a 0.2.0 veve missing `expected_p95_s` falls back to `timeout_s` (or `stall_s` if absent) for stall/reap; pace is skipped (a `pace-blind` warn), never silently masking a hang. The clock always exists; only the pace split is optional.

### 3.2 Checkpoint packet (AS-13, the chess clock)

`{run_id, span_id, status: "incomplete", moves: <int>, last_move_hash: sha256:<hex>, reason: stall|spin|budget|pace, evicted_at: ISO8601}`. Emitted by `checkpointPacket(spanMeta, log, reason)`. Validity: `last_move_hash` resolves in the Legba span log; `moves` == recorded count. Re-enterable; the gate judges, never auto-fails.

### 3.3 Generated CommandPolicy (AS-4 → loa-finn shape)

`toCommandPolicy(veve, cliDir)` emits `{binary, subcommands, deniedFlags, validatePaths}` (the finn interface) + `x_determinism, x_network, x_veve_tree_hash, x_timeout_s, x_rel_required` (the asson extensions finn honors in cycle 5). Generated from the veve; never hand-authored.

## 4 · Component Design

### 4.1 The doctor (`doctor()` — cycle 1, the heart)

Computes EARNED level (AS-3):
- L1: bin exists. L2: `evidence_runs` present (recurrence sensed). L3: veve valid (ajv) AND ≥1 vector passes (`runVectors`) AND attestation valid (`verifyAttestation` — tree-hash matches + sig verifies) AND determinism honest (class consistent with ambient, AS-1/LG-5). L4/L5: CommandPolicy/registry presence (later cycles).
- **Findings**: `claimed > earned` → DRIFT (fail-closed). `declared_by: author` → warn (AS-5, never fails good work). `dev_signature` attestation → `attested-dev` warn (B1). Determinism contradiction → fail (AS-1). daemon claiming L3 → fail (AS-7). CLI with a STATICALLY-RESOLVABLE import outside its dir → warn (AS-14, see below).
- **Earned level ⊥ attestation tier** (IMP-001): two orthogonal axes. A cycle-1 example is L3-by-STRUCTURE (valid veve + passing vectors + valid tree-hash + honest determinism) AND `attested-dev` by TIER (signed with a dev key). The doctor reports both: `earned: L3 (attested-dev)`. "Worked L3 CLI" = L3 structure; the tier upgrades to `attestation` at cycle 3. Neither axis is the other.
- **Exit codes** (IMP-007): `0` = no findings above warn; `1` = a fail-closed finding (claim>earned, determinism lie, broken attestation, daemon-as-L3); `2` = usage error; `3` = warn-only findings present (author-declared, attested-dev, static cross-dir import) — CI may treat `3` as pass-with-annotation. Exit `1` is never ambiguous: it means a mechanical gate failed.
- **Findings emitter** (IMP-015): each finding is `{severity: fail|warn, as_id, message, anchor}` from a single `findings[]` array — no duplicate or split emission.
- Refusal messages teach: `DRIFT: claims L5, earns L2 — claims are cheap, evidence promotes`.

### 4.1b Cross-dir self-containment — best-effort, honest limit (B1/B2, AS-14 reframed)

AS-14 cannot be perfectly enforced by static analysis: dynamic `import()`, `../` traversal, symlinks, and `fs.readFileSync`+eval defeat any AST scan. So the design is honest about the boundary:
- **What tree_hash GUARANTEES**: the exact bytes of every file IN the CLI dir. A swap of any in-dir file is caught (AS-2). This is total over a bounded surface.
- **What the doctor does** (best-effort): a static scan (regex/AST) for `import`/`require` specifiers resolving OUTSIDE the dir → a **warn** finding (exit 3), not a fail. It catches the honest mistake, names the limit.
- **Where the REAL enforcement lives**: runtime, in finn's sandbox — `validatePaths` (FilesystemJail) + network-denied + the generated `x_veve_tree_hash` spawn-time check. Code that reaches outside the dir at runtime is a sandbox concern, not a build-attestation one. asson attests build identity; finn enforces runtime reach. Two layers, named.
- **Documented residual**: a CLI that dynamically loads outside its dir is attested for its in-dir bytes only; its full behavior is governed at the sandbox, not the attestation. v0.3+ may add reproducible-build / closure-hashing.

### 4.2 Attestation (`attestBuild`/`verifyAttestation` — cycle 1 machinery, cycle 3 real key)

`treeHash(dir)` = sorted `path:contenthash` over every file in the CLI dir except `veve.json` (the attestation lives in the veve, so it's excluded — AS-14 coverage). `attestBuild` signs `jcs(veve without attestation block)` with ed25519, records `{tree_hash, git_commit, signed_by_key_id, signature, ts}`. **Cycle 1: `signed_by_key_id` from a local `dev_signature` key**; doctor warns `attested-dev`. **Cycle 3: CI key, `attestation` tier**, doctor passes clean. AS-2: any single-byte edit → tree_hash diverges → `verifyAttestation` false.

**Dev-key lifecycle** (IMP-004): the cycle-1 dev key lives in the existing Legba key dir (`~/.config/loa/audit-keys/asson-dev.{priv,pub}`, 0600), generated once per developer, NEVER committed; its pubkey may be published in OPERATORS.md for local verification. `git_commit` is read from the repo (graceful "uncommitted" sentinel when absent, as the reference demo shows). In CI cycle-1, the demo signs+verifies WITHIN one run (ephemeral key acceptable — the demo proves the machinery, not a trust root). Cycle 3 replaces this with the per-environment CI signing key (`attestation` tier), key custody owned there; rotation = version bump; revocation via hounfour keyring `signer_status`.

### 4.3 Vectors (`harvestVector`/`runVectors` — AS-12/AS-6)

Harvest: run the CLI live, hash canonical stdout, pin `{expect_output_hash, expect_exit}`. Re-run: invoke, recompute hash, compare; mismatch = fail.

- **Text canonicalization** (B4): `stdout_text` is normalized before hashing — UTF-8, LF line endings (CRLF→LF), C locale, trailing whitespace preserved (a tool's trailing newline is part of its contract). `stdout_json` uses JCS. The pin is over the NORMALIZED bytes, so vectors are OS/locale-portable.
- **Non-determinism guard** (B7/IMP-006): `harvestVector` runs the CLI TWICE; if the two canonical hashes differ, it REFUSES to pin (error) and reports the tool as non-deterministic — a `re_executable` declaration is then a lie (the tool is actually `attestable`, caught at harvest, not in CI later). Volatile outputs (timestamps/UUIDs) thus cannot poison the corpus: either the tool is attestable (pin under injected TestClock/seeded Random, noted in the vector name, per the schema), or it's re_executable and stable.

### 4.4 Liveness watchdog (`livenessVerdict` — cycle 4, over Legba span logs)

Reads the Legba move log (just-merged shape): `budgetStatus` (calls vs cap), `detectStall` (silence past `timeout_s`), `detectSpin` (same tool+input ×N, visible from hashes alone), `paceCheck` (past `expected_p95_s`). Verdict ∈ {continue, compact_then_present, reap, checkpoint_and_present}. **AS-16 fallback**: `timeout_s` is the model-free floor — a hard crash/absent heartbeat past the wall = `reap` regardless of log readability. Eviction → `checkpointPacket` (AS-13), never discard. Verdict→action maps onto hounfour `src/integrity/liveness-properties.ts` (reaper/escalation/reconciliation/manual) — cite the law, don't redefine.

### 4.5 Lexicon gate (`lexicon-lint` — cycle 5, the THIRD independent linter, AS-9)

asson's lexicon screens the **legal register only**: banned funds/custody terms with mandatory replacements ("offchain" → "unrecorded internal entry"), untagged testimony (claims resting on memory must carry `[testimony: <person>, conf=<L/M/H>]`), measurement-register mandate (amounts/dates/parties/tx-refs), provenance tiers (attested/documented/testimony/unknown). Runs at the comms seam as ONE of THREE independent linters — alongside `ai-stench-check.mjs` (voice) and `vocabulary-bank` (product), never wrapping them. `rel_required: competitive` arms it; casual → warn-tier. lexicon.json grows by proposal + fixture (collective-choice), never ad-hoc (AS-8/IMP-008).

- **Independence is observable** (IMP-011): the gate emits THREE separate per-linter results (`{linter, exit, findings[]}`), not just an ORed aggregate — a competitive fixture's test asserts that EACH linter fires in its own domain independently (asson catches "offchain", ai-stench catches an em-dash, vocabulary-bank catches an off-brand term) and that one's finding never suppresses another's. The aggregate exit is the OR; the proof is the three separate results.
- **Cycle-5 status** (IMP-012): lexicon-lint ships as a graduated L3 CLI (the `examples/lexicon-lint` is the seed) AND as a comms-seam PreToolUse/outbound gate. It is a PRODUCTION gate for competitive-REL channels from cycle 5, not a scaffold — `rel_required: competitive` channels fail-closed on banned terms; casual channels warn.

## 6 · Security Architecture

Inherits PRD §5b threat model. Caught: tree-hash divergence, claim drift, determinism lie, forged/replayed signature, unrecorded trace_audit, daemon-as-L3. Out of scope (named): malicious-author intent (identity≠intent, the Legba boundary), key custody/recovery (cycle-3 ceremony + hounfour `signer_status` revocation; recovery is residual), compromised CI runner (per-env key isolation partial; reproducible-build later), cross-dir inputs (AS-14 makes the dir the unit). Single-signer trust root accepted this ladder.

## 9 · Design Decisions (SDD-level)

- **D-1 · Vendor canon, don't import** (B6, operator). `src/vendor/canon.mjs` + conformance test. Rationale: zero-NPM-dep + self-contained + fork-proof beats single-source-with-coupling for a package whose entire thesis is self-containment.
- **D-2 · dev_signature is a first-class tier, not a hack** (B1, operator). The doctor has a real `attested-dev` verdict (warn), distinct from `unattested` (fail) and `attestation` (pass). Cycle-1 artifacts are honestly tiered, not fake-trusted.
- **D-3 · Three linters, three exit codes** (B5). The comms gate runs them in sequence; each exits independently; a CI job ORs the exits. No shared lexicon, no orchestrator — asson owns the legal register file only.
- **D-4 · The CLI dir is the attestable unit** (AS-14). Self-containment is enforced, not assumed: a doctor finding on cross-dir imports. Makes tree-hash total over a bounded surface.
- **D-5 · Core stays `.mjs` for cycle 1** (OQ2). Effect is the graduation dialect taught to L3 CLIs, not imposed on asson's own core (the entropy budget: the core is cold skeleton). Revisit if the `effect_type` determinism path needs first-class support.
- **D-6 · The TS↔.mjs importability boundary** (cycle 2). freeside-cli is NodeNext+strict TypeScript; asson is zero-runtime-dep `.mjs` with no types. To let `import { doctor } from "@freeside/asson"` typecheck AND resolve at runtime, asson gains (a) an `exports` map exposing ONLY `"."` → `./src/asson.mjs` (+ a `./liveness` subpath) with a `types` condition, and (b) a hand-written `src/asson.d.ts` declaring the public API. The `.d.ts` is types-ONLY — it adds NO entry to asson's `dependencies` (CL-1 preserved: the core still runs with empty `node_modules`). Deep paths (`@freeside/asson/src/vendor/...`) are deliberately NOT in the `exports` map, so TS cannot couple to internals (CL-7). The verb is a thin translator (CL-3): argv → asson API → console + `process.exit(code)`, exit codes verbatim from the library (CL-4). The asson subcommand is NAMESPACED under `asson <sub>` (CL-2) so it never shadows the existing registry `doctor` verb. The PRD's cycle-2 verb set is `{doctor, harvest, attest, policy}` (§4.5 contracts).
- **D-7 · The drift sensor closes the cycle-1 audit residual** (cycle 2). The conformance test (D-1) proves asson matches its CHECKED-IN golden — it cannot, by construction, detect a change on Legba's side (the golden is frozen; it only goes red on re-vendor). `scripts/check-legba-drift.mjs <legba-core-path>` is the missing upstream sensor: it reads the pinned SHA from `vendor/canon.mjs` + the golden's `generated_from` (asserts internal agreement), and — given a legba-core checkout — compares `git rev-parse HEAD` to the pin. Exit 1 on drift (HEAD ≠ pin), 0 when they match, **3 (warn) when no checkout/git is available** — never 0-when-it-couldn't-check ([[ci-sensors-must-not-be-numb]], CL-6). It SENSES only; re-vendoring stays the manual operator act (B3). Cycle 2 ships the script + a fixture test; the live cross-repo CI job is cycle-3's gate.

## 10 · Test Strategy

- **Invariant tests**: each AS-N ≥1 test citing its ID (`test/as-NN-*.test.mjs`).
- **Negative fixtures close findings by name** (house style): post-attestation-edit (AS-2), claim-drift (AS-3), determinism-lie (AS-1/LG-5), daemon-as-L3 (AS-7), cross-dir-import (AS-14), unrecorded-trace-audit (AS-15), 0.1.0-fork-warn.
- **Conformance**: `canon-conformance.test.mjs` — asson's vendored JCS+ed25519 byte-identical to Legba's on a shared corpus (B6/AS-10).
- **Schema**: ajv validates the 2 example veves + rejects malformed (missing liveness at 0.2.0, bad determinism).
- **Demo-in-CI**: `node src/demo.mjs` exit 0 (smoke gate).
- **Acceptance**: the demo lifecycle reproduced; the hounfour handoff PR carries green vectors.
