## 0 · The one-line frame

Legba is the **run** layer (spans propose, gates validate, tokens carry custody — *safety*: nothing bad happens). Asson is the **build** layer (scripts graduate into CLIs, veve manifests declare them, attestations sign them, the ladder promotes by evidence — *the deterministic skeleton Legba replays*). One ed25519 ceremony, two tenses: build attestation and run attestation. The harness-as-watershed doctrine names the whole: govern the banks, meter the crossings, let the water be water — and **graduate the repetitions** so entropy concentrates where it still buys discovery.

## 1 · Problem Statement

The estate has hundreds of scripts. Nothing governs their lifecycle, so:

1. **Scripts never graduate, or graduate by fiat.** A bash one-liner done twice should become a pinned CLI; today promotion is a vibe, not an evidence gate. There is no veve, no vectors, no attestation — a "CLI" is whatever someone calls a CLI.
2. **Builds aren't attested.** The house refuses public npm (correctly — supply-chain risk); but that leaves OUR artifacts moving by raw file copy with no provenance. A post-attestation code edit (supply-chain swap) is invisible. (The same class the playtest found for runs, now for builds.)
3. **finn's sandbox allowlist is hand-edited.** `CommandPolicy` entries (`loa-finn/src/agent/sandbox.ts:35`) are authored by hand — which means the legality layer drifts from what tools actually are, carries no code-identity, and cannot honor determinism/liveness/REL declarations the tool itself makes.
4. **Liveness is unmetered.** Legba's gates are safety (no skipped gate); but a tool that *hangs* is a span that loiters forever. There is no clock, no stall/spin/budget verdict, no checkpoint-on-eviction — a forced arrival at the gate is dropped work, which punishes arrival and teaches agents to avoid gates.
5. **The legal register leaks.** Competitive-REL contexts (funds, custody, wind-downs, anything a regulator/counterparty reads) have no outbound vocabulary gate. One wrong word — "offchain" for funds — is a standing liability re-injected into every future reader. (The live specimen: the fatBERA wind-down.) This is distinct from AI-voice smell and product vocabulary; it is *legal rules text*.

The materials to fix all five already exist in the estate — they need wiring and a governing ladder, not invention.

## 5 · Functional Requirements (invariants — each gets ≥1 test citing its ID)

Adopted verbatim from the reference PROMPT (AS-1…AS-8), with estate-observed addenda:

- **AS-1** No CLI reaches L3 without: valid veve, ≥1 passing vector, valid attestation, determinism declaration consistent with its ambient list (LG-5 inherited from Legba).
- **AS-2** Tree-hash attestation breaks on any single-byte change to any file in the CLI dir.
- **AS-3** Earned ladder level is derivable from evidence alone; the `claimed` field never feeds any enforcement decision.
- **AS-4** CommandPolicy entries are generated from veves, never hand-authored; carry `x_determinism` + `x_veve_tree_hash`.
- **AS-5** `declared_by: author` always yields a doctor warning (warn-tier, never fail — judgment surfaced, not blocked). Effect-typed CLIs derive class from the requirements channel; non-Effect CLIs earn `trace_audit` via N clean network-denied sandbox runs.
- **AS-6** Vector hashing is canonical: JCS for stdout_json, raw bytes otherwise; exit codes are part of the pin.
- **AS-7** No 0.2.0 CLI reaches L3 without a liveness declaration (`timeout_s`); daemons claiming L3 are a category error (fail). The watchdog consumes Legba span logs; eviction ALWAYS checkpoints (chess clock).
- **AS-8** `rel_required` travels into CommandPolicy as `x_rel_required`; competitive tools in casual-REL rooms are doctor findings (sandbox refusals once finn honors the field). The lexicon gate screens outbound competitive-REL text; every finding carries a replacement.
- **AS-9 (addendum, anti-duplication — operator-load-bearing; OQ1 RESOLVED → three independent linters)**: the lexicon gate is the LEGAL-register layer ONLY. It MUST compose with, never replace, the existing `ai-stench-check.mjs` (LLM-voice layer, Herald verifier) and `construct-vocabulary-bank` (product-vocabulary layer). **Decision (B5)**: the three run as THREE INDEPENDENT LINTERS at one gate — each owns its domain, its own lexicon, its own exit code; asson does NOT orchestrate or wrap the other two (no shared vocabulary, no single owner). The gate is a sequence of three independent checks; a finding from one never suppresses another. asson's lexicon screens funds/custody/regulatory terms only.
- **AS-10 (addendum, ceremony reuse — Legba precedent)**: asson does NOT redefine JCS canonicalization or the ed25519 key-id derivation. It imports them from the Legba/hounfour ceremony (`signed_by_key_id = sha256(signer_id ':' key_version)`, RFC-8785-subset JCS). One ceremony; misalignment is a finding.
- **AS-11 (addendum, recurrence is sensed not requested)**: graduation evidence (`evidence_runs`) comes from the recorder's recorded recurrence or git-log frequency — promotion is PROPOSED by the system, never self-claimed by the script's author. The `claimed` level is an aspiration the doctor checks, not a grant.
- **AS-12 (vector contract, IMP-003 CRITICAL)**: a vector is `{name, argv, stdin|null, expect_output_hash: sha256:<hex>, expect_exit}`. `expect_output_hash` = sha256 of canonical stdout — JCS (RFC-8785 subset) for `stdout_json`, raw bytes for `stdout_text`; exit code is part of the pin (AS-6). Vectors are HARVESTED from live runs (the runs that proved the need), RE-RUN by the doctor + CI, and a vector whose recomputed hash ≠ pinned hash is a doctor failure. The harvest is content-addressed; the re-run is deterministic.
- **AS-13 (checkpoint packet, IMP-002 CRITICAL)**: eviction emits a checkpoint packet `{run_id, span_id, status: incomplete, moves: <count>, last_move_hash, reason: stall|spin|budget|pace, evicted_at}` — never discards work. Validity: `last_move_hash` resolves in the Legba span log; `moves` matches the recorded count; the gate JUDGES the forced arrival (does not auto-fail it). A checkpoint is a chess-clock pause, re-enterable, not a loss.
- **AS-14 (tree-hash coverage, B9)**: `tree_hash` covers EVERY file in the CLI directory (bin + veve + vectors + any local imports), as sorted `path:contenthash` lines. An L3 CLI MUST be self-contained at its directory — a CLI importing code OUTSIDE its dir is a doctor finding (the dir is the attestable unit; build-relevant inputs outside it are out of v0.2 scope, named as a residual).
- **AS-15 (trace_audit evidence is attested, B2)**: the non-Effect `trace_audit` determinism path requires N RECORDED, network-denied sandbox runs — each a recorded move (attested run record), not an asserted count. The doctor reads the recorded evidence; an unrecorded "trust me, it ran clean N times" earns no upgrade.
- **AS-16 (liveness fallback, B3)**: the watchdog reads Legba span logs for stall/spin/budget/pace, BUT `timeout_s` is the model-free, log-independent floor — a hard crash or absent heartbeat past the wall = `reap` regardless of log state. Log rotation is handled by reading the current span head; the soundness (a clock exists) never depends on the log being readable.

## 5b · Threat Model (B4 + B8 — honest about both columns)

**Caught (cryptographically/mechanically):** post-attestation code edit anywhere in the CLI dir (tree-hash divergence, AS-2/AS-14) · a ladder-level claim evidence doesn't support (claim ≠ earned, AS-3) · a determinism lie (declaration contradicts ambient list, AS-1/LG-5) · a forged build signature (ed25519 verify, AS-10) · a replayed attestation reused on a different tree/commit (tree_hash + git_commit binding) · an unrecorded trace_audit upgrade (AS-15) · a daemon masquerading as an L3 skeleton (AS-7).

**NOT caught — by design, named:** a malicious AUTHOR who writes honest-looking, correctly-attested, evil-intent code (asson proves IDENTITY + DETERMINISM, never INTENT — the same boundary as Legba's attestable≠correct; intent is a review/judgment concern, not a gate) · a compromised SIGNING KEY (mitigated by hounfour keyring `signer_status: active|revoked|expired` for revocation + rotation=version-bump; **custody and compromised-key recovery are OUT of scope this ladder, owned by the cycle-3 key ceremony, named as residual**) · a compromised CI runner that signs a bad tree with a valid key (cycle-3 ceremony's per-environment key isolation is the partial answer; full reproducible-build verification is a later rung) · build-relevant inputs OUTSIDE the CLI dir (AS-14 makes the dir the unit; cross-dir shared-lib attestation is v0.3+).

The single-signer / single-environment trust root is accepted for this ladder (the Legba precedent); N-of-M or reproducible-build cross-check are named later hardening.

## 6 · Non-Goals

- **Public npm.** Third-party deps still arrive via lockfile + minimumReleaseAge + ignore-scripts; OUR artifacts move by pinned SHA + attestation + CAS-by-hash.
- **Forcing Effect onto every script.** Effect is the dialect for L3+ where the ceremony pays; L0/L1 bash stays free — that freedom is load-bearing (the entropy budget: cold where it counts, hot where it matters).
- **Merging veve into BeaconV3.** Siblings, aligned philosophy, different scales (CLI vs construct/network). Align fields; do not merge schemas.
- **Duplicating the voice or product vocabulary gates.** asson owns the legal register only (AS-9).
- **Governing daemons.** L3 = terminating skeleton. Long-running infra is governed elsewhere; a daemon claiming L3 fails the doctor (AS-7).
- **Building the recorder.** The flight-recorder exists; asson reads it for recurrence, does not reimplement recording.

## 7 · Technical Constraints

- **ADR-007 firewall (BINDING, CI-enforced).** asson is **network** domain: path `packages/asson/`, commit scope `network/asson/<task>`, beads label `domain:network`. `path-domain-check.yml` blocks cross-domain PRs; no commit touches both platform and network paths. Verbs land in `@freeside/freeside-cli` (doubled name per ADR-007 §D-2), NOT `@freeside/cli` (gaib, platform).
- **Reuse before invention — VENDORED, not imported** (AS-10, B6): asson VENDORS Legba's JCS + ed25519 + key-id-derivation primitives (~30 lines copied into `src/vendor/canon.mjs` with a provenance header citing `legba-core.mjs`), and a CONFORMANCE TEST asserts byte-identical output to Legba's functions on a shared fixture corpus. This keeps the core zero-NPM-dep AND self-contained (no cross-package runtime import) AND fork-proof (the test fails if they diverge). hounfour's `keyring.schema.json` + `signature-envelope.schema.json` shapes and loa-finn's `CommandPolicy` interface are consumed as SHAPES (vendored interface definitions for codegen), NOT runtime dependencies (B7) — cross-repo pieces are PROPOSAL targets (cycle 5), never gated runtime imports. hounfour staging discipline (TypeBox + constraints + vectors, contract_version pinning) is followed for the veve schema handoff.
- **Compose, don't duplicate** (AS-9): `~/.claude/scripts/ai-stench-check.mjs` (Herald verifier, voice) + `construct-vocabulary-bank` (product terms) are the other two layers of the comms gate. asson's lexicon is the third (legal register). The seam is three independent linters at one gate.
- **Zero-dep core.** `src/asson.mjs` stays dependency-free (node:crypto only), like Legba's core — the reference drop already is. A JCS library is imported only if Legba's subset proves insufficient for cross-runtime producers.
- **No root `pnpm-workspace.yaml`.** The monorepo is configured via the root `package.json` `packageManager` field; asson joins as a `packages/*` member following that pattern.
- **Beads discipline.** `domain:network` labels; `br` for lifecycle; no cross-domain blocked-by edges.

## 8b · CI Wiring (IMP-011 + IMP-004 — where the gates actually live)

- **Tests**: `packages/asson/test/*.test.mjs` (node:test, the Legba pattern), each invariant test naming its AS-ID. The demo (`src/demo.mjs`) runs in CI as a smoke gate (exit 0).
- **The doctor gate** (cycle 2): a CI job runs `asson doctor` over the workspace; **exit 1 on any L3+ claim drifting above earned** (mechanical, fail-closed); `declared_by: author` is warn-tier (annotation, never red).
- **Domain CI** (ADR-007): `path-domain-check.yml` + `commit-scope-check.yml` enforce `network/asson/*` scope; asson changes never cross into platform paths.
- **The hounfour handoff has a concrete pass/fail** (IMP-004): the veve schema migration is a PR to loa-hounfour carrying the TypeBox schema + constraint file + ≥10 vectors (valid/invalid) — the same gate the Legba #118 schemas met. "PROPOSAL authored" = a real PR exists with green vector tests, not a doc.

## 9 · Success Metrics (ladder-level)

1. **The demo reproduces in CI** — harvest → attest → doctor L3 → policy, plus all 3 attack fixtures closing findings by name (house style).
2. **One real script graduated end-to-end** with its PR linking the evidence runs (the canonical worked example).
3. **The doctor is a CI gate** — fail-closed on mechanical drift (claim > earned, broken attestation, determinism contradiction); warn-tier on judgment (`declared_by: author`).
4. **Three-layer comms gate proven** — a competitive-REL fixture trips asson's lexicon (legal), ai-stench (voice), and vocabulary-bank (product) INDEPENDENTLY, each in its own domain, none duplicating another.
5. **One ceremony verified** — asson build attestations and Legba run tokens validate under the same key-id derivation; a cross-check test asserts no fork.
