## 1. Problem Statement

The construct estate runs compositions of nondeterministic agents through deterministic seams. The seams claim verification; the territory disagrees. The 2026-06-11 adversarial playtest measured the gap on a live, proven run:

1. **Runs execute unrecorded.** The entire playtest (4 adversarial archetypes + an observer) executed via `agent_call`, leaving `envelope_count 0` — the run only became `valid_run` because the executor *voluntarily* wrapped envelopes afterward. Nothing structural requires execution to leave evidence.
2. **The proof-of-run gate proves presence, not integrity.** `compose-verify-run.sh` check 2 is existence-only (`[[ -f ]]`); a post-emit edit of a segment body is invisible. There is no inter-envelope hash chain — the gate's own comment (lines 41–49) honestly reserves the extension point.
3. **A careful forger passes.** A well-formed hand-written envelope carrying the correct `composition_run_id` + a valid `stage_index` passes schema + set-membership identically to a real one. The gate cannot distinguish authorship.
4. **Enforcement is warn-first prose.** Zero `settings.json` entries auto-fire the gate; the skill text asks agents to honor a number. Quantified gradient: minting a `valid_run` costs ~6 mechanical steps + 2 env vars + the correct base dir; inline role-play costs zero and looks byte-identical.
5. **The verdict is base-dir-dependent.** The same run_id reads `not_a_run` from the repo root and `valid_run` from the substrate base. A real run reads "didn't happen" from where the documentation tells you to stand.
6. **The static maps lie too.** 9 of 29 registry recipes are structurally un-runnable (5 ghost-door constructs with no adapter); three censuses of "what exists" disagree (resolver 16 / packs 35 / adapters 37).

The estate already holds the answer's raw materials: loa's audit chain (`audit_emit`, JCS, Ed25519, trust-store), hounfour's crypto-bearing schema discipline (PhaseCompletionEnvelope house style), rooms-substrate's content-addressed room packets and three-tier handoff validation, and gygax's genuinely re-executable tool family. What is missing is the **substrate that connects them**: hash-chained move recording, deterministic gates that mint signed tokens, and a turnstile that makes custody structural.

**Legba** is that substrate: *spans propose, gates validate, tokens carry custody, the run is a chain of keys.*

## 4. Users & Stakeholders

- **The operator** — gains provable runs: one hash + one public key verifies a multi-hour agentic run.
- **Constructs (workers)** — recording is free (hooks), the token is issued automatically on pass; the governed path becomes the cheapest path (gradient inversion).
- **Verifiers** — gecko (metrics consumer), auditors, and any third party with the run receipt + public keys; challenges are paid by verifiers, not workers.
- **Downstream repos** — hounfour consumers get three new constitutional schemas under the N/N-1 window; rooms-substrate compositions inherit custody without recipe changes.

## 5. Functional Requirements

The reference implementation's eight invariants are adopted as the requirement spine (LG-1…LG-8, from `PROMPT.md`, each requiring at least one test citing its ID), with three estate-observed addenda:

- **LG-1** Every state mutation in a span emits exactly one chained move record; recording is hook-enforced, never agent-voluntary.
  - **LG-1b (addendum, observed)**: hook-enforced AND **wiring-verified** — the gate must prove its hooks are referenced by live settings, not merely present on disk. The estate's observed failure mode (ghost gates: `implement-gate.sh`, `adversarial-review-gate.sh`, `zone-write-guard.sh` shipped but unwired) lives one layer above LG-1.
- **LG-2** Any single-byte alteration of recorded history changes the span head and is caught by gate check `chain` and by `verifyRun`.
- **LG-3** No span with index > 0 opens without a cryptographically valid token from gate index-1 of the same run. Refusal is an error, not a warning.
  - **LG-3b (genesis rule, IMP-002)**: span 0 opens tokenless by definition; gate 0 anchors the chain with `prev_token_hash: GENESIS`. The run receipt binds the genesis anchor so verifiers agree on the chain's first link — no implementation divergence at the first span.
- **LG-4** Every `re_executable` move can be re-executed from CAS at any later time; output-hash divergence is a machine-detectable fraud proof.
  - **LG-4b (environment pinning, blocker B7)**: every `re_executable` move records tool version + environment fingerprint (tool manifest hash). Re-execution under a divergent environment downgrades the move to `attestable` for that challenge — environment drift is never reported as fraud.
- **LG-5** Nondeterministic tools (network, clock, randomness) MUST be recorded `attestable`; a lint flags registry tools lacking a determinism declaration.
- **LG-6** Gate tokens are crypto-bearing and chain-bearing per hounfour conventions, pinned to a `contract_version` literal.
- **LG-7** Semantic checks on attestable content are detector-tier: surfaced and scored, never fail-blocking a gate alone. (Validated by observed behavior: convergence is coherence, not correctness.)
- **LG-8** Validators dispatch on `contract_version` with an {N, N+1} window and explicit activation boundary per run; vectors gate every version bump.
- **LG-9 (addendum, observed)**: tokens are **wave-level** under DAG-parallel fan-out (crs#35 Kahn waves) — issued when a whole wave drains, never per-item; turnstile predicate is `token.wave_number > prior.wave_number`, not stage bump alone.
- **LG-10 (addendum, observed)**: run records live at ONE canonical, root-independent address declared in a SoT; the same run_id MUST yield the same verdict from any working directory. **Decided (blocker B8)**: `~/.loa/runs/<run_id>/`, declared in `~/.loa/deployment.yaml`.
- **LG-11 (addendum, detector scope, IMP-013)**: detector-tier checks on attestable content are a named, non-exhaustive set this ladder: reconstruction tests, evidence-ref resolution, claim-strength tag audit (gygax `observed-trace` vocabulary). Additions are SDD-level; the PRD commits to no more than these.

## 6. Non-Goals

- **Making spans deterministic** or constraining model sampling — the flesh stays free; only the skeleton is replayed.
- **A blockchain, transport, or HTTP server** — hash chains + signatures + git-trackable logs suffice.
- **Retrofitting chains onto legacy runs** — old runs are old-rules runs (fork-boundary discipline; preserve `compose-verify-run.sh`'s refusal posture).
- **Fail-blocking semantic judgment** — wrongness of attestable emissions stays detector-tier (reconstruction tests, sampled audit).
- **N-of-M gatekeepers / operator co-signature** — single-signer per room with key ceremony this ladder; multi-sig is a later hardening rung.
- **Fable routing repair** — the `max ≡ fable` schema-enum gap is a separate operator-gated loa-constructs track, not Legba scope.

## 7. Technical Constraints

- **Cross-repo seating (acknowledged structural friction).** Simstim is single-repo; Legba spans loa-hounfour (law), construct-rooms-substrate (territory), loa (audit machinery reuse), construct-gygax (tool registry), construct-gecko (metrics). **This repo holds the plan, the acceptance harness, and the beads; implementation dispatches per-repo as scoped PRs.** Phase 7 must respect this: `/run sprint-plan` executes what is local; per-repo work is prepared as explicit, reviewable handoffs — never silent cross-repo writes.
  - **Handoff artifact + owner (IMP-009)**: each per-repo dispatch is an L6 structured handoff written to `grimoires/loa/handoffs/` naming the target repo, the rung, the acceptance fixture(s), and the deploy-order position. The operator gates each handoff; the bead carrying it is the tracking record.
  - **Deploy order (blocker B3)**: validators upgrade before producers emit, per rung. A rung's consumer-side validator PR merges and deploys before its producer-side emitter PR. Contract versions ride the hounfour N/N-1 window; skew outside the window is a load-time refusal, not a runtime surprise.
- **CAS redaction floor (blockers B2/B9/B12 — decided here, not deferred).** Cycle 2's recorder records **hashes only** for all tool I/O (input_hash, output_hash over canonical bytes); no raw content enters the CAS this ladder except via an explicit per-tool allowlist rung that ships with its own review. Hash-only recording still supports chain integrity, set-membership, and challenge-by-re-presentation; full content re-execution arrives with the allowlist.
- **Key ceremony minimum shape (blocker B4 — decided here)**: per-room ed25519 keypair generated at room provision; public keys published in the run manifest; `key_version` increments on rotation; `signer_key_id = sha256(id ':' key_version)` per hounfour derivation. GateToken schema (cycle 1) carries `gatekeeper_key_id` + `contract_version` so the ceremony's operational details cannot force a breaking schema change.
- **Token transport (blocker B6 + IMP-012 — decided here)**: cycle 1 GateToken is embedded in the handoff envelope `verdict` (no schema bump, scout-verified binding fields exist); promotion to a first-class envelope field lands at construct-handoff schema v1.2 in the turnstile rung. The GateToken schema itself is transport-agnostic.
- **Authorship scope (blocker B11 — named honestly)**: Legba proves *runtime-custody authorship* — that an artifact passed through the hook-enforced recording + gate path with valid signatures. A compromised hook, a bypassed tool path, or a forged local CAS entry by an attacker with host write access is OUT of scope this ladder; the residual is named in §8 and revisited at the multi-sig rung.
- **Reuse before invention.** loa's `audit_emit` chain mechanics, `lib/jcs.sh` (RFC 8785), Ed25519 signing helper, and trust-store (incl. F1 downgrade-attack detection) are the implementation substrate. Genuinely new: CAS of tool I/O, token mint/verify, replay harness, turnstile.
- **Hounfour house style is law.** New schemas follow `PhaseCompletionEnvelope` (Tier-1/Tier-2 pattern, shared pattern constants, runtime-deferred constraint classification, LOCAL builtins where the DSL can't express cross-tier refs).
- **Secrets in tool I/O.** The existing mutation-logger deliberately omits content (secrets risk). The CAS design MUST address redaction/classification before recording raw tool output (SDD decision; candidate: hash-only for flagged tools, content for allowlisted).
- **Beads discipline.** All tasks carry `domain:shared` labels (substrate work, per ADR-007); `br` for lifecycle, no cross-domain blocked-by edges.

## 8. Risks & Dependencies

| Risk | Severity | Mitigation |
|---|---|---|
| Gradient regression — turnstile adds friction without making the governed path cheapest, worsening defection | HIGH | Measure steps-to-valid-run before/after each rung; token issuance must be automatic on pass; recording must cost the agent zero |
| Cross-repo coordination stalls a rung mid-ladder | MED | Each rung independently shippable + revertible; rung N gates rung N+1; no rung spans more than 2 repos |
| Key custody / malicious gatekeeper | MED | Key ceremony (generate on room provision, version on rotation, publish pubkeys in run manifest); single-signer accepted this ladder, multi-sig deferred and documented |
| Determinism misclassification (LG-5's "main integrity lie") | MED | Determinism manifest required per tool; default `attestable`; lint in CI |
| CAS grows unbounded / holds secrets | MED | Redaction policy decided in SDD before G-3; retention policy per run class |
| Hounfour version-window breakage for existing consumers | LOW | Additive schemas, N/N-1 window, vectors gate the bump (scout: zero conflicts) |
| DAG fan-out races the chain | MED | LG-9 wave-level tokens designed in SDD before any turnstile code |
| Mid-run key compromise (IMP-011) | MED | `key_version` in every token; run receipt binds the key set; rotation mid-run forces a named activation boundary — tokens signed by a revoked version fail verification from the boundary forward |

## 9. Success Metrics (ladder-level)

1. **The playtest re-run flips.** `playtest-the-territory` re-run post-rung-4 reaches `valid_run` with zero voluntary wrapping; the forged-envelope and post-emit-edit attacks are REJECTED with named checks.
2. **Third-party verification.** A run receipt + public keys verify a full composition run with no access to the producing session (rung 5 demo).
3. **Fraud proof fires.** A deliberately confabulated tool output is machine-proven fraudulent by re-execution; the honest twin survives.
4. **Gradient inverted, measured.** Steps-to-count for governed execution ≤ steps for role-play presentation (today: ~6+2 env vars vs 0).
5. **Negative fixtures close findings by name.** Every playtest CONFLICT maps to a fixture that fails pre-Legba and passes post-rung (house fixture discipline).
