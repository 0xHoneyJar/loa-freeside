## Problem

The estate has **no single source of truth** for "which NFT collections exist and their
`{chain, contract, token_standard, world}`." The same facts are hand-authored in ≥5 places —
shadow-audit's `COLLECTION_REGISTRY` env var, sonar's fragmented `constants.ts`, the dashboard's
empty `CONTRACT_REGISTRY: {}` placeholder, worlds' `nft_contracts: []` scaffold — so the **operator
is the integration bus for facts**. The operator named it: *"these questions [contract addresses /
token standards / which collections / RPC URLs] are ones you're asking me too often — we have to
organize… configs and labelling addresses and contracts should be a primitive that not only users
of freeside benefit from but everyone including us as inhabitants (agents + humans)."*

> Sources: 2026-07-03-collections-sot-direction.md; ml-sot-consumers map (6 hand-authored sites);
> operator forks 2026-07-03 verbatim.

## Vision

**Address/contract labelling as a first-class, agent-native primitive.** The agent grounds every
fact it can from the world (belt-gateway pull + on-chain ERC-165 standard detection + the reverse
world-lookup); the operator ratifies instead of hand-authoring; every consumer reads the projection
instead of keeping a hand-maintained copy. Collections is **instance #1** of a reusable
self-grounding registry — the pattern (derive → ratify → read, with a drift sensor) is shaped to
serve agents AND humans AND future Freeside customers, not just this one registry.

**Keystone — PROVEN this session, zero operator input:** chain+contract+collection_key pulled live
from belt-gateway `TrackedHolder` (24 collections); `token_standard` derived on-chain via ERC-165
`supportsInterface` against public RPCs — 20 erc721 + **4 erc1155** classified correctly (catching
the exact silently-wrong case). Full data: `grimoires/loa/context/self-grounded-collections-registry.txt`.

## Goals

| ID | Goal | Metric |
|----|------|--------|
| G-1 | **The primitive exists + is grounded** | A collections SoT holds all 24 tracked collections with `{chain, contract, standard, collection_key, world, role}`; every DERIVED field was agent-grounded (belt + on-chain), not operator-typed |
| G-2 | **Agent-first population** | `freeside collections sync` re-derives the full set READ-only; `propose` writes born-low rows + a ratifiable diff; operator touch = review + author the ≤3 subjective fields per collection |
| G-3 | **Operator-reviewable surface** | The SoT materializes to Postgres (worlds-api) so it's fullstack-native + reviewable — not only a yaml diff; the authored source stays git-versioned |
| G-4 | **First consumer collapsed (settle gate)** | shadow-audit reads the SoT instead of the `COLLECTION_REGISTRY` env var — the FR-1a operator ask is RETIRED and the sandwich-line deploy is unblocked with zero hand-authored config |
| G-5 | **Self-healing drift sensor** | `freeside collections drift` re-derives (belt + on-chain) and fails loud on any row that diverged from ground truth; NEVER silently overwrites an operator-ratified row |
| G-6 | **Reuse-shaped** | The derive→ratify→drift loop is factored so a second registry (RPC endpoints, communities) drops in without a rewrite — collections-concrete, not a speculative framework |

## Non-Goals

- A dedicated collections-registry *building* (EVANS Option B) — trigger: collections grow an
  independent lifecycle (per-collection deploy/revenue).
- Migrating sonar's `constants.ts` to read the SoT — trigger: after the SoT is authoritative
  (sonar is belt's producer; flip it to consumer next).
- Dashboard `CONTRACT_REGISTRY` collapse — next cycle (the empty placeholder waits; not the gate).
- A generic self-grounding-registry *framework* — reuse-shaped only (operator: "collections-first").
- Shared collections (one collection in multiple worlds) — the one-world invariant holds; model as
  read-only reference if ever real.

## Users / Stakeholders

The operator (ratifies + reviews via the pg surface); agents (derive + read — never ask); the
sandwich-line shadow-audit deploy (the first consumer); future Freeside customers onboarding a world
(their collections self-populate); "us as inhabitants" — the primitive is a public good for
agents+humans across the estate.

## Functional Requirements

- **FR-1 (G-1, SoT form — EVANS Option A, cross-repo worlds-api):** the world manifest gains an
  additive `collections` block (schema 1.2 → 1.3): `[{chain, contract, token_standard,
  collection_key, role, provenance}]`. Identity = `(chain, contract)` (immutable, on-chain-grounded);
  `collection_key` = belt routing alias; `role` = world-scoped (primary/companion/lore). Invariant:
  one collection ↔ exactly one world (repository-level unique `(chain, contract)`).
- **FR-2 (G-2, the derive-don't-ask engine, agent-first):** a `freeside collections` CLI verb group
  (modeled on freeside-cli inspect/doctor):
  - `sync` — READ-only: pull belt `TrackedHolder` (chain/contract/collection_key), derive
    `token_standard` on-chain (ERC-165; `unknown` when un-derivable — never assume erc721), propose
    world-binding (reverse `/v1/worlds/lookup` + key-prefix heuristic), print a ratifiable diff.
  - `propose` — write born-low rows into the SoT (`provenance.source_type: ai-derived`,
    `read_state: unread`); subjective fields (world, role) blank + flagged.
  - `ratify <key>` — the operator's sign-off (see FR-3).
  - **Hazard-handled:** `collection_key` normalized `_`→`-` to satisfy the event-schema grammar
    `/^[a-z][a-z0-9-]*$/` (`packages/events/src/schemas/nft-activity.ts`); the diff shows the transform.
- **FR-3 (G-3, agent-first authoring + operator-reviewable ratification):** the authored SoT is
  git-versioned world.yaml (agent writes, agent self-adjusts on re-derive); worlds-api **materializes
  it to Postgres** (`manifest_collections`, reusing last cycle's durable-store precedent) so the
  operator gets a fullstack-native, reviewable surface. Ratification this cycle = the agent opens a
  **PR of derived rows; the operator's merge IS the ratification** (git as the governance gate), with
  the /recall trust-field vocabulary carried in the row frontmatter/columns
  (`ai-derived → operator-validated`) so a review-UI cockpit can layer on later without a schema change.
  The agent can re-derive + self-correct DERIVED fields but NEVER flips a subjective/ratified field.
- **FR-4 (G-4, the settle gate — first consumer collapse, in-repo loa-freeside):** shadow-audit's
  `loadRegistryFromEnv` (`bin/http.ts`) reads the SoT (via the worlds-api projection `GET
  /v1/worlds/collections` or a bundled snapshot) instead of parsing `COLLECTION_REGISTRY`. The env
  var becomes an optional override, deprecated. Kill-test: boot shadow-audit with NO
  `COLLECTION_REGISTRY` env and it serves `GET /v1/collections/:chain/:contract` correctly for the
  ratified set — the FR-1a operator ask is gone.
- **FR-5 (G-5, drift sensor):** `freeside collections drift` re-derives every DERIVED field (belt +
  on-chain) and compares to the SoT: `coherent | drifted | orphaned | unratified | unknown_standard`.
  Drift on an operator-ratified row raises a **contested** flag (never a silent overwrite). Wire as a
  CI/cron check that fails loud (the self-healing pattern).
- **FR-6 (G-6, reuse-shaping):** factor the loop as `ground() → propose() → ratify() → drift()` over
  a small `GroundedRecord` shape (derived-fields + subjective-fields + provenance), so a second
  registry supplies its own `ground()` + field-map and inherits propose/ratify/drift. No framework —
  just no collections-hard-coding in the loop's spine.

## Invariants (every FR must satisfy)

Derive-don't-ask (every field the agent CAN ground, it MUST — only genuinely subjective/secret facts
reach the operator) · agent-never-self-ratifies (DERIVED re-derivable freely; subjective/ratified
fields need the operator's gesture — the /recall force-chain, hook-enforceable) · fail-loud drift
(a live sensor re-derives + flags, never silently overwrites operator truth) · consumers-read-not-copy
(shadow-audit et al. read the projection through their port; they never import the manifest type) ·
one-collection-one-world · public-good shape (the primitive serves agents AND humans).

## Assumptions (falsifiable)

- [ASSUMPTION] the belt-gateway `TrackedHolder` set + on-chain ERC-165 is a sufficient ground source
  for the auditable collections — if a needed collection isn't belt-tracked, that's a sonar-tracking
  gap surfaced by the drift sensor (`orphaned`), not an operator-ask.
- [ASSUMPTION] the world manifest schema accepts an additive `collections` field at 1.3 without
  breaking existing consumers (it's enum-locked additive-only — EVANS confirmed) — if not, FR-1 falls
  back to a worlds-api `manifest_collections` table as the authored source.
- [ASSUMPTION] shadow-audit can read the SoT at boot via a worlds-api projection or a committed
  snapshot without a live dependency that breaks its healthcheck — if the live read is fragile, a
  build-time snapshot of the ratified set ships in-image (the role-snapshot precedent).

## Risks / Gates

- **R-1 (cross-repo):** FR-1/FR-3 land in worlds-api (schema + pg projection); FR-4 in loa-freeside
  (shadow-audit); FR-2/FR-5 (the CLI) in freeside-cli. Coordinate via /coord; operator merges. The
  in-repo settle gate (FR-4) can be proven against a committed snapshot even before worlds-api's live
  projection ships.
- **R-2 (standard un-derivable):** legacy contracts without ERC-165 → `unknown` → ratify-only; never
  assume. The drift sensor classifies these `unknown_standard` for operator attention.
- **R-3 (ratification-mechanism drift):** the operator wants pg/review-friendly *eventually* but
  agent-first *now* — this cycle ships git-PR ratification with the trust-field vocabulary in place so
  the pg-cockpit is additive later, not a re-architecture. Don't over-build the review UI now.
- **R-4 (world-binding ambiguity):** `puru_*` binds to a purupuru world not on the deployment registry
  — the propose step flags it `unratified`/`orphaned`; the operator ratifies the binding (or files
  the missing world). Exactly the ratify case, not a blocker.
