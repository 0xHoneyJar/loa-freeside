# Go-Live Path D · Railway + Managed NATS

> **The fast, Railway-first path to a real Berachain mint → real Discord post.** Skips AWS NLB / VPC peering. Uses a managed NATS broker (Synadia NGS free tier) so all three consumers (sonar on Envio · characters bot on Railway · dash on Railway) talk through a single public endpoint. JWKS published as a static file. **Portability**: the substrate library already abstracts the bus via `NatsLike`; future migration to Kafka/Redpanda/SQS is per-consumer connection-init swap (~10 lines), not a library rewrite.

## Step-by-step (operator action)

### Step 1 — Synadia NGS account + creds (~5 min)

1. Sign up at Synadia Cloud (their managed-NATS product — search "Synadia Cloud" or "Synadia NGS" for the current portal URL; the cloud landing page evolves and I haven't verified a specific URL today)
2. Free tier: create an account → generate an `account-creds.creds` file from the dashboard
3. **Read the NATS server URL from Synadia's dashboard** (will look like `tls://<region-host>:4222` — exact host depends on the region/account; I do not have a verified current value to insert here)
4. **Output**: `NATS_URL` value (from the dashboard) + the `.creds` file contents (this is BOTH the auth credential AND the broker trusts Let's Encrypt so no separate CA is needed)

> **Alternative if Synadia signup is friction**: any managed-NATS host works (NATS.io has a list of providers). Or self-host with `nats-server` on Fly.io / Hetzner / a Railway "NATS template" if one exists — see Option AD-2 below. The substrate-library cares only that the URL is reachable + the creds work; broker provenance is operator's choice.

Synadia's `.creds` file is JWT-based auth — nats.js v2.28+ has built-in support via the `creds` config option. No separate CA needed (Synadia's broker uses Let's Encrypt; nats.js trusts system roots).

**Important wiring note**: our current substrate code passes `tls: { ca: <file> }` from `NATS_TLS_CA`. For Synadia we want `nats.js` to use system roots AND consume the creds file. This needs a small substrate wire update — see §"Substrate adaptation" below.

### Step 2 — Host the JWKS file publicly (~10 min)

The JWKS document is at `~/.loa-secrets/cluster-events-pillar-v1/jwks.json`. Pick the simplest publisher:

**Option 2a — Vercel** (recommended; cleanest URL):
1. `mkdir /tmp/jwks-publish && cd /tmp/jwks-publish`
2. `cp ~/.loa-secrets/cluster-events-pillar-v1/jwks.json ./`

4. `cd /tmp/jwks-publish && vercel deploy --prod` (will auto-generate a `<slug>.vercel.app` URL)
5. `EVENTS_JWKS_URL` = `https://<slug>.vercel.app/.well-known/jwks.json`

1. Create a public gist with the JWKS content
2. Use the raw URL: `https://gist.githubusercontent.com/<user>/<gist-id>/raw/jwks.json`

## Substrate adaptation needed for Synadia (NATS creds)

The current substrate code (`packages/events` lib + `freeside-sonar/src/lib/events-publisher.ts` + `freeside-characters` bot wire) accepts `NATS_TLS_CA` as a file path + uses it as `tls: { ca: <pem> }`. Synadia's NATS uses JWT-based auth via a `.creds` file, NOT mTLS.

**Two paths to handle this**:

### Option AD-1 — substrate-side adapter (cleanest, ~30 min of work)

Add `NATS_CREDS_FILE_CONTENT` env support to each consumer:
- At boot, if `NATS_CREDS_FILE_CONTENT` is set, write it to a temp path (`/tmp/nats.creds`) and pass `authenticator: nats.credsAuthenticator(readFileSync(...))` to `connect()`.
- Falls back to `NATS_TLS_CA` mTLS when `NATS_CREDS_FILE_CONTENT` is unset.

This is a follow-up commit on each consumer. ~20 lines per consumer. Not blocking the cycle close (current code works against any TLS-mTLS broker; just doesn't speak Synadia's auth flow).

### Option AD-2 — self-host NATS instead of Synadia (~15 min, no code change)

Provision a tiny VPS (Hetzner CX11 / Fly.io VM / DigitalOcean droplet) running `nats-server` with TLS+mTLS. Generate a CA + per-service certs. Substrate works as-is.

Trade: more infra to manage. But the existing substrate code is unchanged.

**Recommendation**: Option AD-1 (substrate adapter). It's a small substrate evolution that makes the library more portable (Synadia, Confluent Kafka with creds, AWS MSK IAM auth, etc. all use creds-file auth patterns). Worth the 30 min.

## Portability — what swapping the bus looks like

The substrate library `@0xhoneyjar/events` defines minimal interfaces:

```typescript
// In publisher.ts:
interface NatsLike {
  publish(subject: string, data: Uint8Array, opts?: { headers?: unknown }): void | Promise<unknown>;
}

// In subscriber.ts:
interface NatsLike {
  subscribe(subject: string, opts?: unknown): NatsSubscriptionLike;
}
```

These are the ONLY ties to NATS in the library itself. Everything else (envelope, JCS, signer, topics, hash chain) is bus-agnostic.

**To swap the bus** (e.g. NATS → Kafka):
1. Write a thin Kafka adapter that satisfies `NatsLike` (~30 lines): `publish` maps to producer.send; `subscribe` returns an async iterator over consumer messages.
2. Each consumer (sonar / characters / dash) swaps `connect()` from nats.js for the Kafka adapter init.
3. Topics may need renaming (NATS subjects vs Kafka topics — but the cluster's Hounfour 3-segment convention works in both).
4. ACVP envelope semantics (sig, hash chain, payload schema) are completely unchanged.

Total swap cost: ~30 lines per consumer + a thin adapter. Done in a single morning if/when scale or cost drives the decision.

**This is the operator-stated invariant**: the event bus is a substrate-mechanism, not a substrate-coupling. The cycle delivered on this.

## Rollback (per step)

Each step is independently reversible:
- **Step 7**: `MST_CANARY_ENABLED=0` → redeploy → no Discord posts (substrate keeps running)
- **Step 5**: leave bot's `NATS_URL` empty → bot keeps booting, events subscriber disabled cleanly per the rd-1 fail-soft contract
- **Step 4**: leave sonar's `NATS_URL` empty → indexer continues writing to Envio Postgres, no publishes happen (per BB#24 rd-1 fail-soft)
- **Step 3**: stop the dash Railway service. The cluster is unaffected.
- **Step 2**: take down JWKS host. Subscribers will surface `signature-invalid` for every envelope — visually loud but not catastrophic. Existing posts in Discord persist.
