# `jcs-subset/v0` — the pinned canonicalization rule (GV6 reference ruler)

**Purpose:** the byte-exact rule a third party (`loa-freeside/evals`) must implement to
reproduce an Echelon `cert_hash`. This is the **reference ruler** for the GV6 byte-match
gate (issue #178). Authority is **pinned**: FORGE `spec/JCS_SUBSET_V0.md @ 20626a23`,
mirrored byte-for-byte by `backend/utils/jcs_subset.py` (stdlib-only). A FORGE spec bump is
a *recorded seam event* — never silent tracking.

> **Key reframing of the "canonicalizer" seam.** `jcs-subset/v0` is **RFC 8785 narrowed to a
> validated input domain**. Per FORGE spec §4, *RFC 8785 over the pre-validated subset domain
> is byte-identical to `jcs-subset/v0`*. So a **faithful** full-RFC-8785 canonicalizer
> (`canonicalize@2`) **will** byte-match this vector — the seam is not "subset vs full 8785 by
> construction," it's "is your 8785 impl faithful on the subset domain?" The shared vector is
> exactly where you confirm that. The two known ways a hand-rolled canonicalizer diverges are
> (1) **number formatting** (Python `json.dumps`/`repr` ≠ ECMAScript `Number::toString`) and
> (2) **key sort** (Unicode *code-point* order ≠ UTF-16 *code-unit* order). Both are pinned below.

---

## 1. Input domain (fail-closed — reject, never normalize)

A producer MUST reject (raise) rather than silently coerce anything outside this domain:

| Rule | Detail |
|---|---|
| Types | `dict` (string keys only) · `list` · `str` · `bool` · `int` · `float` · `null`. Any other type → reject. |
| `int` magnitude | `abs(value) ≤ 2^53 − 1` (`Number.MAX_SAFE_INTEGER`). Above → reject (JSON.stringify loses precision). |
| `float` | finite only — no `NaN`, no `±Inf` → reject. |
| Strings (keys **and** values) | MUST be Unicode **NFC**. Non-NFC → reject (no silent normalization). |
| Strings | no lone surrogates (U+D800–U+DFFF) → reject. |
| Object keys | MUST be strings. |

## 2. Serialization (produces a UTF-8 byte string, no whitespace)

Dispatch by type (note: `bool` is checked **before** `int`):

- **`null`** → `null`
- **`bool`** → `true` / `false`
- **`int`** → decimal digits, `str(value)` (no exponent; safe-range guaranteed by the domain)
- **`float`** → **ECMAScript `Number::toString`** (ECMA-262 §7.1.12.1), NOT `json.dumps`:
  - `0` and `-0.0` → `0`
  - otherwise the **shortest round-tripping** decimal digits, formatted by the 5 ECMAScript cases:
    decimal when `k ≤ n ≤ 21`, fractional when `0 < n ≤ 21`, leading-zero fractional when `-6 < n ≤ 0`,
    else exponent `mantissa e±exp` (e.g. `1e20` → `100000000000000000000`, `1e21` → `1e+21`).
  - (Reference impl: `_ecmascript_number_to_string` in `jcs_subset.py` — Python `repr(float)` gives the
    shortest digits since 3.1; reformat per the cases.)
- **`str`** → `"` + escaped chars + `"`, where each code point `cp`:
  - shorthand escapes: `0x08→\b  0x09→\t  0x0A→\n  0x0C→\f  0x0D→\r  0x22→\"  0x5C→\\`
  - else if `cp < 0x20` → `\u` + 4 **lowercase** hex digits (`\u%04x`)
  - else emit the character **verbatim** (including all non-ASCII, `/`, U+2028, U+2029 — JSON.stringify does NOT escape these)
- **`list`** → `[` + serialized elements joined by `,` + `]`
- **`dict`** → `{` + (`serialized_key` + `:` + `serialized_value`) for each key, joined by `,` + `}`,
  with keys sorted by **UTF-16 code-unit order** == bytewise compare of the **big-endian UTF-16**
  encoding (`key.encode("utf-16-be")`). This diverges from code-*point* order only for
  supplementary-plane (astral) characters.

Final output: the UTF-8 encoding of the serialized string.

## 3. `cert_hash` recipe (NORMATIVE for third parties)

```
cert_hash(envelope) =
  1. doc      := envelope                       # the served document
  2. stripped := doc with forge_seam.calibration_ref REMOVED
                 # remove ONLY that one key. echelon_owned_risk_flags and
                 # forge_owned_risk_flags_seen REMAIN in the hash input.
  3. bytes    := jcs_subset_canonical(stripped) # §2 above
  4. return "sha256:" + hex(sha256(bytes))
```

`calibration_ref` is excluded because it embeds `cert_hash` itself plus the deployment-dependent
`cert_uri` (a self-reference that would otherwise be uncomputable). `verdict_id` uses the same
canonicalizer over `{"subject": …, "factors": …}` (computed before composition).

## 4. Confirm against the shared vector

`gv6-cert-vector.json` (this directory) carries a real envelope + its `expected_canonical_utf8`,
`expected_canonical_sha256`, and `expected_cert_hash`, all generated by Echelon's shipped
`compute_cert_hash`. To confirm `loa-freeside/evals`:

1. Run your canonicalizer on `stripped_document` → compare **byte-for-byte** against `expected_canonical_utf8`.
   (Canon-layer check — isolates number/sort divergence before hashing.)
2. `sha256` your bytes → compare against `expected_cert_hash`.
3. Independently: take `envelope_document`, run the §3 recipe end-to-end → same `expected_cert_hash`.

Primitive-level vectors for the canonicalizer alone (ints, floats, unicode, key-sort edge cases)
live in `backend/tests/vectors/jcs-test-vectors.json` (generator: `_generate_jcs_vectors.py`) — use
those to localize a divergence to a specific serialization rule.

If bytes diverge, the GV6 gate's diagnostic (being added) reports
`{diverged_layer: canon|schema|grading, canon_strategy, first_diverging_offset}` so the mismatch
names itself — no silent invalid.
